# EXP27 frozen 12-task compatibility pilot

This implementation realizes only the EXP25 minimum: 11 fresh 30-second tasks on `exp04_cm_n480_k08_r02`, then one fresh 300-second IPSNS seed-1 task on `exp13_lodes_de_commute`. Its nominal cap sum is 630 seconds, with one CPU, 8 GB and a one-hour Slurm allocation. The Wulver `debug` partition/QOS admits this one-hour request; a read-only Slurm scheduling test estimated immediate availability, whereas `general`/`low` estimated a later start. This queue choice changes scheduling, not method caps or resources. No EXP13 deterministic task or EXP11/22 graph-cap cell is rerun. Inputs and output witnesses remain in private Wulver storage; Git contains hashes, configuration, code, and later sanitized audit summaries only.

`protocol.json` is the immutable roster, hashes, algorithm parameters, and deadline rule. `campaign.py` verifies the graph bytes and canonical hashes against EXP25, the project baseline Git revision and IPSNS file hash, the Xiong source revision and binary hash, the EXP13 adapter release, and dependency versions. It refuses an existing output directory. `worker.py` executes each method under the parent's monotonic deadline. It serializes only complete order events; Xiong restart and insertion initializer events can remain useful after a valid timeout. IPSNS exposes only its final order in this interface. The project insertion implementation retains its 1,000-move rule, but receives the *remaining task deadline* instead of EXP12's fixed 105-second internal deadline. A three-second controller shutdown reserve and four-second worker inner reserve protect strict end-to-end caps; these are part of the frozen EXP27 protocol and do not confer equal algorithmic work.

`audit.py` imports no method implementation or worker scoring function. It independently reopens and hashes each graph, computes canonical weighted identity, parses complete orderings, recomputes integer backward weight, checks the retained DAG, verifies Xiong's weighted `W` conversion, compares reported objectives, and checks event/checkpoint timing. It writes a 12-row task inventory, report, and checksums. The Slurm script runs the controller and auditor sequentially in one persistent job, so audit completion is independent of the Codex session. A nonzero audit exit leaves every original task file intact and identifies violations.

## Private Wulver procedure

1. Archive an exact Git commit to a new read-only release directory, add a `RELEASE_REVISION` file containing that commit, and verify file hashes. Supply the frozen EXP13 adapter release, baseline and Xiong source checkouts and binary, the two existing DIMACS paths, one **new** output directory, and an existing compatible Python environment through the `EXP27_*` variables required by `run.sbatch`.
2. Before submission, run `python -m experiments.exp27_compat.campaign` with the same paths and `--preflight-only`, verify all twelve identities and 630 cap seconds, confirm current Slurm allocation limits, and check for an equivalent queued/running job. Read-only parser and validator smoke checks on the LODES input may use its already audited EXP13 deterministic order; this is not a new task.
3. Submit `run.sbatch` once with a new private Slurm log and output path. Record the job ID, release revision, start, node and resources. The job writes `manifest.json`, `progress.json`, each task's `process.log`, complete order events, `checkpoints/*.json`, and then `audit_report.json`, `task_inventory.csv`, `checksums.sha256`. Do not use an output path that has ever existed.
4. If the job fails, preserve the entire failed output. Inspect `fatal.json`, logs and checkpoints, then make a separately versioned repair decision. Do not overwrite or silently retry completed tasks. The LODES 300-second availability gate passes only if the independent report credits a complete objective by the deadline without an INVALID status.

No pilot objective is part of the public 5,254-outcome extension or the manuscript's nine tables. The pilot is a compatibility and availability test on two selected, dependent-in-purpose graph views, not evidence of a universal method ranking. A broader campaign needs a separate decision after the completed independent audit and rights/access review.
