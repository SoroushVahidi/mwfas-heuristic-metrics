# EXP11 controlled-budget feasibility pilot

This protocol was frozen before new pilot outcomes were inspected. Five original weighted DIMACS graphs are selected by ID and checked against EXP10's independent canonical inventory and byte hashes. Four synthetic graphs use 1, 10, and 30 seconds; CollegeMsg uses 120 seconds. Three arms and two top-level seeds yield exactly 78 tasks and at most 1,704 seconds of nominal task budgets. Tasks run sequentially on one Wulver CPU in one allocation.

`xiong_single` invokes the unchanged Xiong `fas_alg` once as `W RASstar -r SEED -p -o RANKS`. `xiong_restarts` invokes it repeatedly with the prespecified distinct seed sequence. Conversion, launches, each run, parsing, and validation share one deadline. Every completed restart is checked on the original weighted graph before an objective can enter the event log; retained improving ranks are independently rechecked by the post-run auditor. `ipsns_frozen` invokes the unchanged 200-iteration function with EXP04/05 parameters. No ranking is available until its final CSV is written. A killed run therefore has no objective unless a complete independently verified output was checkpointed before the deadline. Progress text alone is insufficient.

The task timer starts before worker launch. A controller kills the process group slightly before the nominal limit to reserve termination time, and records actual elapsed wall time, child CPU time, exit code, and whether the full end-to-end cap was met. Timeouts and failures remain in the inventory. A timed-out restart arm can have a separately labeled best completed-restart objective. Sources and original graph files are read-only. Raw graphs, ranks, logs, and third-party code stay outside Git; the versioned report contains metadata only.

The [COCO methodology](https://coco-platform.org/) motivates fixed instances, repeated stochastic trials, explicit budget definitions, and treating missing target hits as censored. Its function-evaluation unit does not transfer across these implementations because their operations differ; wall time and CPU time are both recorded. [COCO performance assessment](https://numbbo.github.io/coco-doc/perf-assessment/) prefers fixed-target runtimes and anytime target curves when valid incumbent traces exist; this pilot instead asks a fixed-wall-budget question and will not infer IPSNS targets from incomplete logs. [Dolan and Moré](https://doi.org/10.1007/s101070100263) use performance profiles to compare solver runtime ratios over many problems; five selected graphs and many censored endpoints are insufficient for a stable profile, so individual outcomes and denominators are shown. [Restart-schedule research](https://arxiv.org/abs/1206.3286) supports explicit schedules and independent seeds; this pilot uses a deterministic seed sequence and counts all restart overhead. [Xiong et al. (2024)](https://doi.org/10.1016/j.cor.2024.106724) study feedback-arc heuristics, but the paper's cardinality FAS setting does not establish weighted MWFAS fidelity. The private original executable, weight-preserving invocation, and independent integer-weight audit provide that fidelity here.

The selection is diagnostic. It cannot establish population-level algorithm superiority. Future graphs, targets, and hypotheses must be fixed without selecting only favorable pilot cases.
